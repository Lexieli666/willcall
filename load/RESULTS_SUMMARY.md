## The four resume bullets, against what was measured

The project plan lists four bullets that follow "if targets are met". Each is reproduced verbatim
below with every figure in it replaced by the measured one, and with the parts that are **not
supported** marked. A bullet is only usable once nothing in it is marked.

<!-- BULLETS:BEGIN -->
### 1. Scope and deployment

> Built a seat-reservation service in Java and TypeScript (Spring Boot, PostgreSQL, Redis, React) and deployed it on AWS with Terraform; GitHub Actions deploys every merge.

- The service exists and is built as described.
- **Not supported: "deployed it on AWS".** There are no credentials on the build host. The Terraform is written and passes `terraform fmt -check` and `terraform validate`; `terraform plan` has never run. The deploy workflow exists and skips rather than fails when no cloud role is configured.
- **Usable form:** "…and packaged it for AWS with Terraform, validated in CI; GitHub Actions runs the full suite on every merge."

### 2. Load and correctness

> Sold 5,000 seats to 10,000 buyers arriving within 10 seconds with zero oversells across 50 load runs; hold requests held 121 ms p99 at 1,000 req/s and live seat updates reached 5,000 SSE clients at 180 ms p99.

- **Flash sale:** 50/50 runs with invariants intact, 0 oversells, 0 server errors.
- **SSE:** 5,000 established, 0 failed; propagation 223 ms (p50 113 ms, includes the 50 ms coalescing window). The plan guessed 180 ms; the measurement is what it is and the target band was 80–250 ms.
- **Not supported: "121 ms p99 at 1,000 req/s".** Measured sustainable rate on this hardware is 200 requests/s (67 per replica) with nothing shed and p99 under 150 ms. At 1,000 requests/s the p99 is 4,564 ms, with 37,929 of 57,693 requests shed — above this stack's ceiling, see the sweep above.
- **Usable form:** "…zero oversells across 50 load runs; holds answered at 24 ms p99 at the measured sustainable rate of 200 req/s on three 2-vCPU replicas, and live seat updates reached 5,000 SSE clients at 223 ms p99."

### 3. Accessibility

> Made the seat map operable by keyboard and screen reader; CI blocks any merge with an axe violation or a Lighthouse accessibility score below 100.

- **Lighthouse accessibility:** 100, enforced as a budget in CI. axe runs on every route and state in the end-to-end suite and CI fails on a violation.
- A Playwright test completes a whole purchase using only key events, including two-dimensional arrow navigation of the seat grid. There is no `click()` in that spec.
- **Not supported: "operable by screen reader".** That is a claim about whether announcements are *useful*, which axe cannot decide. The manual NVDA and VoiceOver passes are listed as not done in `docs/accessibility.md`.
- **Usable form:** "…operable by keyboard, with an ARIA grid and live regions built for screen readers; CI blocks any merge with an axe violation or a Lighthouse accessibility score below 100."

### 4. Operations and reach

> Ran a game day against the live service, published the postmortem of a connection-pool outage, and shipped to 40 real users in a public demo; 310 tests, 82% backend coverage.

- **Game day:** 4 scenarios (exhaust-pool, inject-latency, kill-replica, restart-redis); invariants held after 4/4, 0 server errors; 3 re-run to verify a fix.
- **The connection-pool postmortem exists** and is the most substantial of the four: the application shed correctly and the edge proxy turned that into nine seconds of `502`. Its fixes were verified by re-running the scenario.
- **Coverage:** 85.14%.
- **Tests:** 280 (151 backend, 106 frontend unit, 23 end to end).
- **Not supported: "shipped to 40 real users in a public demo".** It has not happened. That also leaves [ADR 0012](../docs/adr/0012-hold-ttl.md) at `proposed` and the hold TTL an unvalidated default.
- **Usable form:** "Ran a game day against the running service and published four postmortems, including a connection-pool outage where the proxy turned graceful load shedding into a total outage; fixes verified by re-running the scenario."

## What is not measured

Listed so its absence is a decision rather than an oversight.

- **Nothing on AWS.** No credentials on the build host. The Terraform is written and validated;
  `terraform plan` has never run.
- **No production propagation measurement.** The 5,000-connection figure comes from the load
  scenario. The server publishes its own flush duration; the client half is not instrumented.
- **No Interaction to Next Paint.** It is a field metric needing real sessions. Total Blocking
  Time, its lab proxy, is reported instead and is 0 ms.
- **No screen-reader verification.** Ten manual checks are listed as not done in
  `docs/accessibility.md`.
- **No real users.** The public demo has not happened, so [ADR 0012](../docs/adr/0012-hold-ttl.md)
  stays `proposed` and the hold TTL remains an unvalidated default.
